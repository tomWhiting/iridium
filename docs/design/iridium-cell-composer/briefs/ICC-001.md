## Requirements

### R1: Borrowed kernel cell rows and grapheme geometry

WHEN a caller prepares CellRowMap from a borrowed Document, its actual FoldState and explicit CellWrapParameters, the kernel SHALL produce immutable screen rows for the lifetime of those borrows. It SHALL use workspace unicode-segmentation and unicode-width without GPU dependencies; expose scalar/byte/grapheme/cell boundaries, row placements, hit testing and row spans from the same measurements; and implement decisions D1-D7. Preparation SHALL NOT clone or hash the full document to validate freshness, mutate editor state, trim whitespace, or use document id/revision as an independent cache authority. Methods take no replacement document. Invalid positions are typed errors; hidden positions are explicit non-placement. Zero-width layouts are explicit empty layouts and never divide by zero.

**Acceptance:**
- cargo test -p iridium-editor --no-default-features cell_layout covers widths 0,1,2,4,8,10,80; empty text, empty lines, CR/LF/CRLF, trailing newline, exactly-full last row, tabs, wide glyphs, combining clusters, flags, skin-tone emoji and ZWJ sequences.
- For "alpha beta gamma" at width 10, rows are exactly "alpha beta" and " gamma". Concatenated source spans reproduce every original scalar/byte, including leading/trailing spaces. There is no word-break backtracking and no invented final empty row for an exactly-full non-newline-ending line.
- Every positive-width grapheme is indivisible across rows. A tab that crosses the row end is placed at the next row origin and remeasured from that origin; an atom wider than the entire width is represented once as an overflow atom, never split or retried indefinitely. R3 clips it using existing blanking behavior.
- place and position_at obey the canonical laws in D6, including explicit wrap affinity, trailing whitespace, dead cells before wide glyphs, zero-width clusters and row-end edge positions. Do not assert a false bijection for zero-width clusters or tab continuation cells.
- Doctest compile_fail demonstrates that changing Document or FoldState while the row map is used fails to compile. A runtime divergent-clone fixture creates equal id/revision but different text and proves independently borrowed maps describe their actual sources; no map method accepts the other clone.
- Fold visibility comes from the borrowed FoldState::is_line_hidden contract and produces each visible document line once, including nested folds. It never reuses the unrelated web FoldState or changes fold-visual Viewport units.

### R2: Cell-aware command dispatch and complete grapheme-safe input

WHEN the host opts into Editor cell-key, cell-command, cell-pointer or cell-paste entry points, the kernel SHALL use the existing keymap resolver, command IDs, repeat handling, auto-pair provenance and reversible-command/history path. Geometry-dependent commands SHALL prepare the borrowed row map from current editor state internally, obtain the result, end immutable layout borrows, then apply the command exactly once. The implementation SHALL provide visual-row Up/Down/Page/Home/End and selection variants, grapheme-atomic horizontal movement/deletion and range-safe word/edit operations as D8-D10 define. No parallel physical-key switch is permitted. Existing Editor::handle_key/run_command/paste semantics for current faces remain unchanged. No resize or layout synchronization may call set_content, rebuild Editor, reset undo or mutate the legacy Viewport. All errors precede document/history mutation.

**Acceptance:**
- Unit tests exercise resolved command IDs through both key events and direct command dispatch. Rebinding cursor.lineDown to another key still yields a visual-row move in cell mode; host commands/chords/repeat suppression retain their existing results. No hardcoded Enter/Alt-Enter send decision is added.
- Left/Right, Backspace/Delete, word delete and selection replacement never leave half a combining sequence, ZWJ family, regional-indicator flag or emoji modifier. Test both scalar-interior host selection refusal before mutation and post-insert normalization when new text joins a preexisting grapheme.
- Unicode-safe Backspace preserves the real owned-pair and multi-character auto-pair collapse rules. User-supplied closers are not treated as owned. Combining marks adjacent to pair delimiters cannot cause partial-grapheme deletion.
- Up/Down traverse continuation rows with sticky CELL columns, preserve preferred position through short rows, skip folded content and preserve selection direction. Home/End address the visible row; document-start/end still address the document. Page commands use the actual visible text-row count, including zero-height behavior without invented limits.
- Cell affinity/preferred columns are outside persisted Position, CursorState, Command, UndoTree and legacy Viewport. Resize/tab-width/fold changes and nonvertical movements invalidate stale preferences without losing undo branches. Undo/redo restores exact document bytes and serialized selections; it does not replay obsolete screen affinity.
- Paste of multiline Unicode text is one reversible operation with original text unchanged, never a series of simulated key presses. Paste never produces a submit command. Typing, auto-pair insertion, resize, paste, undo, redo and branch creation preserve the existing history grouping contract.
- For ordinary typing/copy/host commands the cell-mode dispatcher does not prepare a whole-document row map when only local grapheme validation is needed. Geometry work is limited to geometry-dependent operations; no content clone/hash comparison is added per key.
- ICC-AST-01: keyboard/mod.rs contains module/import declarations and re-exports only; KeyboardHandler public path and all behavior remain identical after moving its type and implementation to handler.rs. Existing sibling field/helper access uses pub(super), never pub(crate). New handler file is below500 physical lines. Exact move proof, focused keyboard/public editor/TUI tests, strict workspace Clippy and supplemental AST bind the new43-path source set; previous42-path diagnostics remain historical.

### R3: Borrowed cell Frame preparation and optional bare chrome

WHEN Frame::prepare_cells borrows an Editor and explicit CellFrameOptions, the face SHALL derive text extent/chrome allocation once, prepare the kernel map from those exact borrows and return PreparedCellFrame. Frame::render_cells SHALL accept that prepared object and a same-sized local CellBuffer, not an independent editor. Render, caret, selections and hit testing SHALL consume the same prepared row geometry. Absent chrome SHALL reserve no status, search, gutter or sidebar cells. Existing Frame::render/layout/sync_viewport signatures and their default output/scroll semantics SHALL remain unchanged. New composer rendering SHALL NOT enter raw mode, own ANSI output, read a TTY, run a driver, or mutate the Editor. An extent mismatch is a typed error before any buffer write.

**Acceptance:**
- Frame mod.rs contains declarations/re-exports after moving its existing Frame/PaintedLine definitions and legacy rendering logic unchanged into named modules. Existing public exports remain available.
- Bare 0x0, 0xN, Nx0, 1x1 and larger buffers render without out-of-range writes or hidden reserved status rows. A nonzero parent-origin fixture copies local cells at one offset and leaves sentinel cells outside the allocated rectangle unchanged; the Iridium API returns local coordinates only.
- Prepared extent mismatch is rejected without changing a sentinel-filled destination. Compile-fail examples prove the borrowed editor cannot be edited between preparation, rendering and hit-testing. Reprepare after resize works with the same Editor/history.
- No second wrap scanner exists in the face. LineLayout preserves existing public within-line results while deriving cluster widths/byte/scalar spans from the kernel measurement. Frame styles, syntax spans and selections keep original document byte/scalar coordinates when one line occupies several rows.
- Caret hints and hit testing agree with D6/D11. Exact-full final rows and an oversized CJK glyph at width 1 remain bounded; a trailing-edge caret is explicit, not a false hit-test round trip. No partial glyph or ANSI/control character is emitted.
- Existing legacy frame tests remain green and fixed expected-cell fixtures prove identical output for default chrome, hidden/visible gutter, sidebar, status, open search overlay, horizontal clipping, folded placeholder, Unicode/tabs and search/selection styling. New optional Some(chrome) allocation uses existing chrome rules and None is bare.
- Composer pointer mutation uses the R2 fresh cell-pointer entry point with current options. Prepared hit tests are read-only queries; no owned stale geometry/token can later mutate a different editor.
- Fixed expected descriptors cover CRLF as invisible legacy cluster, combining/ZWJ/CJK/tab byte/scalar/cell spans; strict CellLine retains explicit line-ending and overflow errors. No error-to-empty conversion.
- Each actual primary/secondary cursor uses its validated cell affinity. Invalid index returns None; actual state/options changes invalidate affinities. Multi-cursor soft-break upstream carets remain upstream; legacy primary API is unchanged.
- Review repair ICC-R3-01: bind syntax-cache reuse to the same document and an immutable Rope snapshot using the existing locked ropey instance-equivalence API. Retain ownership so address reuse and divergent Document clones cannot reuse foreign spans. Permit only the existing workspace ropey dependency for iridium-tui and its lockfile dependency-list membership; no version/checksum churn. Same unchanged document preserves cache reuse. Reused-versus-fresh Frame tests cover equal-revision different documents and divergent same-id clones. Record the retained snapshot copy-on-write cost for subsequent performance validation.
