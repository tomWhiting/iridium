# Data Model: Viewport-Aware Syntax Rendering

**Feature**: 002-viewport-syntax-rendering
**Date**: 2026-01-14

## Entities

### 1. HighlightSpan

A single syntax highlight range within the document.

| Field | Type | Description |
|-------|------|-------------|
| `start` | `usize` | Start byte offset (inclusive) |
| `end` | `usize` | End byte offset (exclusive) |
| `highlight_type` | `HighlightType` | Category of syntax element |

**Validation Rules**:
- `start < end` (non-empty span)
- `end <= document_length` (within document bounds)

**Notes**:
- Spans may overlap (e.g., a keyword inside a function)
- Spans may cross line boundaries (multi-line strings, comments)
- Byte offsets are into the full document, not visual content

---

### 2. HighlightType

Enumeration of syntax highlight categories.

| Variant | Description |
|---------|-------------|
| `Keyword` | Language keywords (if, else, fn, etc.) |
| `String` | String literals |
| `Comment` | Comments (single and multi-line) |
| `Number` | Numeric literals |
| `Function` | Function/method names |
| `Type` | Type names |
| `Variable` | Variable names |
| `Operator` | Operators (+, -, =, etc.) |
| `Punctuation` | Brackets, delimiters |
| `Property` | Object properties |
| `ConstantBuiltin` | Built-in constants (true, false, null) |
| `VariableBuiltin` | Built-in variables (this, self) |
| `FunctionBuiltin` | Built-in functions |
| `Parameter` | Function parameters |
| `Tag` | HTML/JSX tags |
| `TagAttribute` | Tag attributes |

---

### 3. SpanIndex

Container for efficient span queries by byte range.

| Field | Type | Description |
|-------|------|-------------|
| `lapper` | `Lapper<usize, HighlightType>` | Interval tree for O(log n) queries |
| `span_count` | `usize` | Total number of spans indexed |
| `max_span_length` | `usize` | Longest span (for query optimization) |

**Operations**:
- `build(spans: Vec<HighlightSpan>)` - Create index from spans
- `query(start_byte: usize, end_byte: usize)` - Find overlapping spans
- `is_empty()` - Check if any spans exist

**Invariants**:
- Index is immutable after creation (rebuilt on highlight update)
- All spans in index are valid (non-empty, within bounds)

---

### 4. ViewportState

Current visible region for span queries.

| Field | Type | Description |
|-------|------|-------------|
| `first_line` | `usize` | First visible document line (0-indexed) |
| `visible_lines` | `usize` | Number of lines visible in viewport |
| `scroll_offset_y` | `f32` | Sub-line scroll offset (pixels) |
| `overscan_factor` | `f32` | Buffer zone multiplier (default: 2.0) |

**Derived Values**:
- `query_start_line`: First line to include in span query (with overscan)
- `query_end_line`: Last line to include in span query (with overscan)
- `start_byte`: Byte offset of query_start_line
- `end_byte`: Byte offset of query_end_line

---

### 5. EditInfo

Information about a document edit for incremental parsing.

| Field | Type | Description |
|-------|------|-------------|
| `start_byte` | `usize` | Byte where edit began |
| `old_end_byte` | `usize` | Byte where old content ended |
| `new_end_byte` | `usize` | Byte where new content ends |
| `start_position` | `(usize, usize)` | (row, column) where edit began |
| `old_end_position` | `(usize, usize)` | (row, column) where old content ended |
| `new_end_position` | `(usize, usize)` | (row, column) where new content ends |

**Usage**:
- Passed to tree-sitter's `tree.edit()` for incremental reparsing
- Generated by the controller on each document modification

## Entity Relationships

```
┌─────────────────┐
│   Document      │
│   (ropey Rope)  │
└────────┬────────┘
         │ contains text at byte offsets
         ▼
┌─────────────────┐         ┌─────────────────┐
│  SpanIndex      │◄────────│  SyntaxTree     │
│  (rust-lapper)  │ produces│  (tree-sitter)  │
└────────┬────────┘ spans   └────────┬────────┘
         │                           │
         │ query(start, end)         │ edit() + reparse()
         ▼                           ▼
┌─────────────────┐         ┌─────────────────┐
│  ViewportState  │         │    EditInfo     │
│  (visible area) │         │  (incremental)  │
└─────────────────┘         └─────────────────┘
```

## State Transitions

### SpanIndex Lifecycle

```
Empty → Built → Queried → Rebuilt (on content change)
  │               │           │
  └───────────────┴───────────┘
        (rebuild replaces entirely)
```

### Incremental Parse Flow

```
User Types
    │
    ▼
Generate EditInfo
    │
    ▼
tree.edit(editInfo)
    │
    ▼
parser.parse(content, oldTree)
    │
    ▼
Extract changed spans (or all spans if significant change)
    │
    ▼
Rebuild SpanIndex
    │
    ▼
Query visible spans
    │
    ▼
Render
```

## Memory Considerations

| Entity | Size Estimate | Scaling |
|--------|---------------|---------|
| HighlightSpan | ~24 bytes | O(spans) |
| SpanIndex | ~24 bytes/span + overhead | O(spans) |
| ViewportState | ~32 bytes | O(1) |
| EditInfo | ~48 bytes | O(1) |

For a 10,000-line file with ~50,000 spans:
- SpanIndex: ~1.2 MB
- Typical viewport query returns ~500 spans: ~12 KB
